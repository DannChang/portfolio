# Virtual DJ Booth — CDJ-3000 Controller (/dj)

**Date:** 2026-06-10
**Status:** Approved (autonomous session — design decisions documented here and in the PR)

## Goal

A new `/dj` route with a working, playable two-deck DJ rig rendered in Three.js:
two CDJ-3000-style players flanking a 2-channel mixer. Users can load their own
audio files onto either deck (file picker or drag-and-drop), then actually mix:
play/cue/scratch, beat-match with tempo faders, blend with EQ/filter/faders and
the crossfader. Audio is real (Web Audio API), not simulated.

## Constraints & decisions

- **Stack:** Next 13 app router + react-three-fiber + drei. No new dependencies.
- **Dedicated `<Canvas>` for this route** (deliberate divergence from the repo's
  shared tunnel-canvas pattern): with the shared canvas, r3f listens on the
  layout wrapper, so pointer events from the DOM overlay (load buttons, links)
  bubble into r3f and get raycast into the scene — clicking "Demo track" could
  also press a hidden 3D control. A dedicated canvas binds events to the canvas
  element itself, which makes that class of bug impossible. Verified empirically
  during this build.
- **Responsive camera:** the rig is wide; on narrow viewports a fixed camera
  clips the decks. The camera pulls back proportionally to aspect ratio
  (clamped 1–1.9×) so the whole rig stays in frame.
- **Offline-safe:** no external models, fonts, or HDRIs. All geometry is
  procedural; all text is canvas-texture based.
- **Audio engine** is plain JS (`src/helpers/audio/`), independent of React.
  Components bind to it imperatively (`useFrame` reads state each frame; controls
  write directly). React state is only used for DOM chrome (track titles, etc.)
  via a tiny subscribe/emit bus.
- **Two demo tracks are synthesized client-side** (OfflineAudioContext, 124 and
  128 BPM house loops) so the booth is playable instantly with zero assets and
  the mixing flow can be verified end-to-end.

## Architecture

```
app/dj/page.jsx                DOM shell: load buttons, drag-drop, hints
src/components/canvas/dj/
  DJRig.jsx                    scene: 2 decks + mixer, lights, camera, controls
  CDJ3000.jsx                  one deck: jog, screen, transport, loops, tempo
  Mixer.jsx                    trim/EQ/filter knobs, faders, crossfader, VU
  controls.jsx                 Knob / Fader / PushButton / Label / drag plumbing
src/helpers/audio/
  DJEngine.js                  decks + mixer graph + transport logic
  bpm.js                       onset-flux autocorrelation BPM estimator
  waveform.js                  peak extraction (detail + overview)
  demoTracks.js                synthesized demo loops
```

### Audio graph (per channel)

```
deck source ─ deck out ─ trim ─ low ─ mid ─ high ─ filter ─ fader ─ xf ─ master ─ analyser ─ destination
                                              └─ channel analyser (pre-fader, for VU)
```

- EQ: low shelf 100 Hz, peaking 1 kHz, high shelf 10 kHz; −26 dB…+6 dB (DJM-style).
- Filter knob: single knob → low-pass (left) / high-pass (right), neutral center.
- Crossfader: equal-power curve; channel faders: squared taper.
- Gain changes use `setTargetAtTime` to avoid zipper noise.

### Transport (per deck)

`AudioBufferSourceNode` playback with variable `playbackRate`
(tempo ±6/10/16 % + jog nudge). Position is tracked by folding elapsed
context time into an anchor on every rate change; loops use native
`loop/loopStart/loopEnd` with wrap-aware position math. Cue, 4 hot cues,
manual loop in/out, 4-beat auto loop, reloop/exit, BPM sync (matches the other
deck's effective BPM, no phase alignment). Jog: drag while paused = scrub;
drag while playing = pitch bend (BufferSource cannot play in reverse, so
back-spins clamp to heavy slowdown rather than reverse — documented limitation).

## Out of scope (documented in PR)

Master tempo (key lock), true reverse scratch, phase-aligned sync/beatgrids,
3-band colored waveforms, headphone cueing (browsers expose one output),
recording, keyboard shortcuts.

## Verification
